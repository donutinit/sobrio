# sobrio v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajustes (página aparte, CSS por interruptores, modo oscuro, piezas del switcher, excepciones con comodines, gancho de tema), nueva pestaña propia y control de velocidad de medios.

**Architecture:** Un modelo `settings` en `storage.local`, validado por funciones puras en `settings.js` y `style.js`; las páginas (content scripts, switcher, ajustes, nueva pestaña) leen `settings` y `theme` y escuchan `storage.onChanged`. El gancho de tema son variables `--sobrio-*` que el background lee de `userContent.css`.

**Tech Stack:** igual que v0.1 (JS plano, `node --test`, `tools/*.py`); fuentes OFL de Fontsource.

**Spec:** `docs/superpowers/specs/2026-10-14-sobrio-v0.2-design.md`

## Global Constraints

- Todo lo de Global Constraints de v0.1 sigue (sin npm, permisos, atajo, commits, textos).
- Defaults y rangos exactamente como en el spec (`DEFAULTS`); actualizar desde v0.1 no cambia nada visible.
- Patrones: `example.com` exacto; `*.example.com` = ese dominio y subdominios.
- Variables del gancho: `--sobrio-background`, `--sobrio-text`, `--sobrio-text-muted`, `--sobrio-selection`, `--sobrio-border`, `--sobrio-accent`, `--sobrio-corners`, `--sobrio-font`.
- Atajos de velocidad: `]`, `[`, `\`, sin modificadores y fuera de campos editables.
- Ningún permiso nuevo en el manifest.

## Review Focus

- `settings` corrupto o de otra versión en `storage` (tipos raros, números fuera de rango, colores inválidos): todo cae a defaults campo por campo. Test en Task 1.
- Patrones pegados como URL completas, con mayúsculas o puertos, y basura: se normalizan o se rechazan. Test en Task 1.
- Apagar todas las piezas del switcher: la UI no deja apagar la última, y `modes()` con todo apagado devuelve al menos bookmarks. Test en Task 3.
- Atajos de velocidad mientras se escribe en un campo editable (input, textarea, contenteditable): no hacen nada. Prueba de navegador en Task 6.
- Gancho de tema con valores inválidos (`--sobrio-corners: banana`, color `red`): se ignoran uno por uno. Test en Task 1.

### Task 1: `settings.js`

**Files:** Create `settings.js`, `test/settings.test.js`; Modify `boot.js`, `test/state.test.js` (se borra: `siteState` se prueba en settings), `manifest.json` (content scripts: `boot.js`, `settings.js`, …).

**Produces** (en `globalThis.sobrio.settings` y `module.exports`):
- `DEFAULTS` (spec), `mergeSettings(stored) → settings` (copia profunda; cada campo con tipo y rango válidos o su default; motores desconocidos fuera; reglas inválidas fuera).
- `hostMatches(pattern, host) → boolean`, `normalizePattern(input) → string | null`.
- `siteState(stored, host) → {dark, css}` con patrones.
- `matchingPatterns(list, host) → string[]` (para que `td`/`ta` quiten y para la etiqueta).
- `parseThemeHook(get: (name) => string) → theme | null` (`{background, text, textMuted, selection, border, accent, corners, font}`, cada uno opcional; `null` si no hay nada).
- `darkTheme(dark, theme) → objeto para DarkReader.enable`.
- `desiredSpeed(speed, host) → number`, `stepSpeed(value, step, dir) → number` (acotado entre 0.25 y 4, redondeo a 2 decimales).

- [ ] Tests primero (incluye Review Focus: settings corrupto, patrones raros, gancho inválido), verlos fallar, implementar, verlos pasar, commit `add settings model`.
